React, TypeScript y Vite desde cero

Del warning de VS Code a una aplicación biomédica tipada

Autor/a

BioForja

Fecha de publicación

4 de agosto de 2026

1 Propósito y resultado

Este tutorial resuelve el warning que aparece en settings.json y usa el problema como punto de entrada para aprender TypeScript, React y Vite. Al finalizar podrás:

  • comprender por qué VS Code subraya determinadas preferencias;
  • distinguir JavaScript, TypeScript, React y Vite;
  • crear un proyecto React con TypeScript;
  • modelar datos biomédicos mediante tipos e interfaces;
  • construir componentes, propiedades, estado y eventos;
  • ejecutar pruebas, aplicar lint y generar una compilación de producción;
  • incorporar esta página .qmd a un sitio Quarto sin reemplazar su tema.
NotaUna precisión importante

TypeScript sí es un lenguaje de programación. React es una biblioteca para construir interfaces y Vite es una herramienta de desarrollo y compilación. Los tres se complementan, pero no cumplen la misma función.

2 Diagnóstico del warning de VS Code

2.1 Qué muestran las líneas subrayadas

La configuración contiene estas cuatro preferencias:

"typescript.updateImportsOnFileMove.enabled": "prompt",
"javascript.updateImportsOnFileMove.enabled": "prompt",
"typescript.preferences.importModuleSpecifier": "shortest",
"javascript.preferences.importModuleSpecifier": "shortest"

Su sintaxis es válida y los valores también lo son. El subrayado naranja no significa que el archivo JSON esté roto. Indica que las claves se consideran obsoletas en las versiones actuales de VS Code.

Desde VS Code 1.110, publicado en febrero de 2026, las configuraciones separadas javascript.* y typescript.* se están reemplazando por configuraciones unificadas js/ts.*. Las opciones antiguas todavía funcionan, pero VS Code las marca como deprecated y una opción unificada tiene prioridad cuando ambas existen. Consulta las notas oficiales de VS Code 1.110.

2.2 Corrección recomendada

Elimina las cuatro claves antiguas y usa solamente estas dos:

// React, JavaScript y TypeScript
"js/ts.updateImportsOnFileMove.enabled": "prompt",
"js/ts.preferences.importModuleSpecifier": "shortest",
"csharp.semanticHighlighting.enabled": true

La equivalencia es exacta:

Configuración antigua Configuración actual Función
javascript.updateImportsOnFileMove.enabled js/ts.updateImportsOnFileMove.enabled Pregunta si debe actualizar imports al mover un archivo
typescript.updateImportsOnFileMove.enabled js/ts.updateImportsOnFileMove.enabled La misma regla, ahora compartida
javascript.preferences.importModuleSpecifier js/ts.preferences.importModuleSpecifier Define el estilo de rutas para imports automáticos
typescript.preferences.importModuleSpecifier js/ts.preferences.importModuleSpecifier La misma preferencia, ahora compartida

La configuración "prompt" conserva el comportamiento equilibrado: VS Code no modifica imports sin avisar. El valor "shortest" elige el import disponible con la ruta más corta. Ambas claves actuales están registradas por la extensión integrada de TypeScript de VS Code en su manifiesto oficial.

2.3 Aplicar y verificar la solución

  1. Abre settings.json con Preferences: Open User Settings (JSON).
  2. Reemplaza las cuatro claves antiguas por las dos claves unificadas.
  3. Guarda el archivo.
  4. Ejecuta Developer: Reload Window desde la paleta de comandos.
  5. Coloca el cursor sobre las claves: no debe aparecer el mensaje de obsolescencia.
  6. Crea temporalmente un archivo importado, muévelo en el explorador y comprueba que VS Code pregunta si debe actualizar sus imports.
TipCómo comprobar una configuración sin adivinar

Ejecuta Preferences: Open Default Settings (JSON) y busca el nombre de la clave. Esa vista muestra las preferencias que la versión instalada de VS Code reconoce. La referencia oficial de configuraciones describe este procedimiento.

2.4 Si el mensaje dice “Unknown Configuration Setting”

Ese sería un problema distinto. Las dos causas más comunes son:

  1. La extensión integrada está deshabilitada. En Extensiones (Ctrl+Shift+X), escribe @builtin typescript, abre TypeScript and JavaScript Language Features y selecciona Enable.
  2. La opción está en un bloque incorrecto. Las claves deben estar en el nivel principal de settings.json, no dentro de workbench.colorCustomizations ni dentro de otro objeto que no admita esa preferencia.

Después ejecuta Developer: Reload Window. Las extensiones integradas no se desinstalan; pueden deshabilitarse y volver a habilitarse, como explica la documentación de JavaScript en VS Code.

3 El mapa mental del ecosistema

Antes de escribir código conviene separar las capas:

Tecnología Qué es Qué aporta Qué no hace por sí sola
JavaScript Lenguaje ejecutado por el navegador Lógica, eventos y acceso a APIs web No verifica tipos estáticos
TypeScript JavaScript con un sistema de tipos Detecta inconsistencias antes de ejecutar El navegador no ejecuta TypeScript directamente
React Biblioteca de interfaz Componentes, estado y renderizado declarativo No instala ni compila el proyecto
Vite Herramienta de desarrollo y build Servidor rápido, transformación y producción No define la interfaz ni el modelo de datos
JSX/TSX Sintaxis para describir una interfaz Permite combinar marcado y lógica de componentes No es HTML literal ni un lenguaje independiente

La idea esencial es esta: escribimos componentes React en archivos .tsx; TypeScript comprueba el contrato de los datos; Vite transforma el proyecto y entrega JavaScript al navegador.

4 Preparar el entorno

4.1 Requisitos

Necesitas:

  • VS Code actualizado;
  • la extensión integrada TypeScript and JavaScript Language Features habilitada;
  • Node.js compatible;
  • npm, incluido con Node.js.

Comprueba las versiones:

node --version
npm --version

La versión actual de Vite exige Node.js 20.19+ o 22.12+; una versión mayor compatible también sirve. Verifica siempre el requisito vigente en la guía oficial de Vite.

AdvertenciaEvita instalaciones globales innecesarias

No necesitas sudo npm install -g vite. El generador npm create vite@latest y las dependencias locales del proyecto funcionan sin privilegios de administrador.

4.2 Extensiones recomendadas en VS Code

Instala únicamente lo que aporta una función clara:

Extensión Identificador Uso

5 Crear el primer proyecto

React recomienda actualmente usar un framework para aplicaciones completas y Vite cuando se desea aprender React desde una configuración cliente sencilla. La guía oficial de React incluye Vite entre las herramientas apropiadas para este segundo caso.

Desde la carpeta donde guardas tus proyectos:

npm create vite@latest bio-signal-dashboard -- --template react-ts
cd bio-signal-dashboard
npm install
npm run dev

Abre la dirección local que muestre la terminal, normalmente http://localhost:5173. Para abrir el proyecto en VS Code:

6 Fundamentos mínimos de JavaScript

TypeScript amplía JavaScript; no lo sustituye. Antes de React debes reconocer variables, funciones, arreglos, objetos, módulos y operaciones inmutables.

const signalName = "ECG";              // valor que no se reasigna
let selectedCount = 0;                  // valor que sí puede cambiar

const qualities = [92, 78, 88];
const accepted = qualities.filter((value) => value >= 80);
const normalized = qualities.map((value) => value / 100);

const signal = {
  id: "ECG-001",
  sampleRate: 500,
  reviewed: false,
};

const reviewedSignal = { ...signal, reviewed: true };

Observa dos ideas importantes para React:

  • map y filter producen nuevos arreglos en lugar de modificar el original;
  • { ...signal, reviewed: true } crea un objeto nuevo con una propiedad actualizada.

Los módulos dividen el programa en archivos:

// quality.ts
export function qualityLabel(value: number): string {
  return value >= 80 ? "Aceptable" : "Revisar";
}

// otro archivo
import { qualityLabel } from "./quality";

El warning inicial está relacionado precisamente con estos imports: VS Code puede actualizar "./quality" si quality.ts cambia de nombre o ubicación.

7 TypeScript: modelar antes de programar

7.1 Inferencia y anotaciones

TypeScript suele inferir el tipo sin que lo escribas:

const modality = "ECG";   // TypeScript infiere string
const sampleRate = 500;    // TypeScript infiere number

Anota tipos cuando expresan un contrato útil, especialmente en parámetros y retornos:

function durationSeconds(samples: number, sampleRate: number): number {
  return samples / sampleRate;
}

Esto se detecta antes de abrir la aplicación:

durationSeconds("5000", 500);
// Error: string no puede usarse donde se espera number.

7.2 Uniones: estados válidos y finitos

Una unión limita un valor a alternativas conocidas:

export type SignalKind = "ECG" | "EMG" | "EEG";
export type ReviewState = "pending" | "approved" | "rejected";

SignalKind evita variantes accidentales como "E.C.G" o "ecg". La documentación de TypeScript explica cómo las uniones representan valores con varias alternativas permitidas.

7.3 Interfaces: el contrato de los datos

Crea src/types.ts:

export type SignalKind = "ECG" | "EMG" | "EEG";

export interface SignalRecord {
  id: string;
  participantCode: string;
  kind: SignalKind;
  sampleRate: number;
  quality: number;
  reviewed: boolean;
  notes?: string;
}

La propiedad notes? es opcional. Una interfaz describe la forma que debe tener cada registro. TypeScript no valida por sí solo datos externos en tiempo de ejecución; si los registros provienen de una API o archivo, todavía debes validarlos al ingresar al sistema.

7.4 Evitar any

any desactiva la protección de TypeScript. Para datos externos aún no validados, usa unknown:

function parseExternalData(value: unknown): SignalRecord {
  if (typeof value !== "object" || value === null) {
    throw new Error("El registro no es un objeto válido");
  }

  // En una aplicación real continuaríamos validando cada propiedad.
  throw new Error("Validación todavía no implementada");
}

La frontera correcta es: datos externos → validación → tipos internos confiables.

8 React: construir la interfaz con componentes

8.1 JSX y TSX

Un componente React es una función que devuelve una descripción de interfaz:

function Header() {
  return (
    <header>
      <h1>BioSignal Dashboard</h1>
      <p>Control de calidad de señales biomédicas</p>
    </header>
  );
}

El archivo usa .tsx, no .ts, porque contiene JSX. En JSX:

  • className reemplaza el atributo HTML class;
  • las expresiones JavaScript se escriben entre {};
  • un componente debe empezar con mayúscula;
  • cada bloque retornado necesita una raíz común.

8.2 Props: datos que entran al componente

Crea src/components/SignalCard.tsx:

import type { SignalRecord } from "../types";

interface SignalCardProps {
  signal: SignalRecord;
  onToggleReviewed: (id: string) => void;
}

export function SignalCard({
  signal,
  onToggleReviewed,
}: SignalCardProps) {
  const qualityClass = signal.quality >= 80 ? "quality-ok" : "quality-warning";

  return (
    <article className="signal-card">
      <div>
        <span className="signal-kind">{signal.kind}</span>
        <h2>{signal.id}</h2>
        <p>Participante: {signal.participantCode}</p>
        <p>Frecuencia de muestreo: {signal.sampleRate} Hz</p>
      </div>

      <div className="signal-status">
        <strong className={qualityClass}>Calidad: {signal.quality}%</strong>
        <button
          type="button"
          onClick={() => onToggleReviewed(signal.id)}
        >
          {signal.reviewed ? "Marcar pendiente" : "Marcar revisada"}
        </button>
      </div>
    </article>
  );
}

SignalCardProps es el contrato del componente. Si quien lo usa omite signal, entrega otro tipo o define una función incompatible, TypeScript lo detecta.

import type indica que SignalRecord se necesita solo durante la verificación y no debe convertirse en un import de JavaScript en producción.

8.3 Estado: información que cambia

React usa Hooks para incorporar capacidades a un componente. useState permite recordar información entre renderizados. Los Hooks se llaman en el nivel superior del componente, nunca dentro de un if, ciclo o función anidada. Consulta las reglas y Hooks integrados de React.

Reemplaza src/App.tsx por lo siguiente:

import { useState, type ChangeEvent } from "react";
import "./App.css";
import { SignalCard } from "./components/SignalCard";
import type { SignalKind, SignalRecord } from "./types";

type Filter = "ALL" | SignalKind;

const initialSignals: SignalRecord[] = [
  {
    id: "ECG-001",
    participantCode: "P-014",
    kind: "ECG",
    sampleRate: 500,
    quality: 94,
    reviewed: true,
  },
  {
    id: "EMG-002",
    participantCode: "P-021",
    kind: "EMG",
    sampleRate: 1000,
    quality: 76,
    reviewed: false,
  },
  {
    id: "EEG-003",
    participantCode: "P-008",
    kind: "EEG",
    sampleRate: 256,
    quality: 87,
    reviewed: false,
  },
];

function isFilter(value: string): value is Filter {
  return value === "ALL" || value === "ECG" || value === "EMG" || value === "EEG";
}

export default function App() {
  const [signals, setSignals] = useState<SignalRecord[]>(initialSignals);
  const [filter, setFilter] = useState<Filter>("ALL");

  const visibleSignals = signals.filter(
    (signal) => filter === "ALL" || signal.kind === filter,
  );

  const averageQuality = visibleSignals.length
    ? Math.round(
        visibleSignals.reduce((sum, signal) => sum + signal.quality, 0) /
          visibleSignals.length,
      )
    : null;

  function handleFilterChange(event: ChangeEvent<HTMLSelectElement>) {
    const value = event.target.value;
    if (isFilter(value)) {
      setFilter(value);
    }
  }

  function toggleReviewed(id: string) {
    setSignals((currentSignals) =>
      currentSignals.map((signal) =>
        signal.id === id
          ? { ...signal, reviewed: !signal.reviewed }
          : signal,
      ),
    );
  }

  return (
    <main className="app-shell">
      <header className="hero">
        <p className="eyebrow">BioForja · Biomedical AI</p>
        <h1>BioSignal Dashboard</h1>
        <p>Revisión trazable de calidad para ECG, EMG y EEG.</p>
      </header>

      <section className="toolbar" aria-label="Controles del tablero">
        <label htmlFor="kind-filter">Modalidad</label>
        <select
          id="kind-filter"
          value={filter}
          onChange={handleFilterChange}
        >
          <option value="ALL">Todas</option>
          <option value="ECG">ECG</option>
          <option value="EMG">EMG</option>
          <option value="EEG">EEG</option>
        </select>

        <output>
          Calidad promedio: {averageQuality === null ? "Sin datos" : `${averageQuality}%`}
        </output>
      </section>

      <section className="signal-list" aria-live="polite">
        {visibleSignals.map((signal) => (
          <SignalCard
            key={signal.id}
            signal={signal}
            onToggleReviewed={toggleReviewed}
          />
        ))}
      </section>
    </main>
  );
}

8.4 Qué estás aprendiendo en App.tsx

Expresión Concepto
useState<SignalRecord[]> Estado genérico: solo acepta un arreglo de registros válidos
type Filter = "ALL" \| SignalKind Composición de uniones
value is Filter Guardia de tipos y estrechamiento seguro
.filter(...) Dato derivado; no necesita otro estado
.reduce(...) Agregación de datos
setSignals(current => ...) Actualización basada en el estado anterior
{ ...signal, reviewed: ... } Actualización inmutable de un objeto
key={signal.id} Identidad estable de cada componente en una lista
onChange y onClick Manejo declarativo de eventos

No guardamos visibleSignals ni averageQuality en estado porque ambos se calculan a partir de signals y filter. Duplicar estado obliga a sincronizar copias y crea errores evitables; React recomienda evitar estado redundante.

React considera el estado de objetos y arreglos como solo lectura: se reemplaza con una nueva estructura en lugar de mutarse. Este patrón está documentado en useState.

9 Cómo trabaja Vite

9.1 Desarrollo y actualización rápida

npm run dev

Vite inicia un servidor local y actualiza los módulos modificados sin recargar toda la aplicación. Este mecanismo permite ver cambios de componentes y estilos casi inmediatamente.

9.2 Compilación de producción

npm run build

La plantilla react-ts ejecuta la verificación de TypeScript y luego genera la versión optimizada en dist/. Vite usa index.html como entrada y produce recursos aptos para alojamiento estático, según su guía de compilación.

Prueba localmente esa versión:

npm run preview

preview sirve para revisar el resultado compilado; no es el servidor que debe usarse como infraestructura de producción.

9.3 Variables de entorno

Crea .env.local:

VITE_API_BASE_URL=http://localhost:8000

Úsala con tipo string:

const apiBaseUrl = import.meta.env.VITE_API_BASE_URL;
ImportanteNo guardes secretos en variables VITE_

Toda variable con prefijo VITE_ queda expuesta al código cliente y puede inspeccionarse en el navegador. Nunca pongas allí contraseñas, llaves privadas ni tokens sensibles. Consulta la documentación oficial de variables de entorno.

10 Calidad de código en VS Code

10.1 Configuración moderna para el proyecto

Puedes guardar preferencias compartidas en .vscode/settings.json dentro del proyecto:

{
  "editor.formatOnSave": true,
  "js/ts.updateImportsOnFileMove.enabled": "prompt",
  "js/ts.preferences.importModuleSpecifier": "shortest",

  "[javascript][javascriptreact][typescript][typescriptreact]": {
    "editor.defaultFormatter": "esbenp.prettier-vscode",
    "editor.codeActionsOnSave": {
      "source.organizeImports": "explicit",
      "source.fixAll.oxc": "explicit"
    }
  }
}

Esta configuración mantiene confirmación al mover archivos, formatea al guardar y aplica correcciones disponibles de Oxlint. La extensión oficial Oxc reconoce source.fixAll.oxc. Si el equipo no quiere compartir preferencias personales, conserva estas claves en la configuración de usuario y no confirmes .vscode/settings.json en Git.

10.2 Oxlint

La plantilla React + TypeScript actual de Vite 8 incluye Oxlint y un archivo .oxlintrc.json. Ejecuta:

npm run lint

Oxlint analiza patrones problemáticos; TypeScript comprueba contratos de tipos; Prettier decide formato. Son responsabilidades distintas. El package.json oficial de la plantilla permite verificar qué herramienta incluye la versión actual.

NotaSi tu plantilla todavía usa ESLint

No migres solo por seguir el tutorial. Conserva dbaeumer.vscode-eslint y "source.fixAll.eslint": "explicit" mientras package.json ejecute ESLint. La configuración del editor debe corresponder a las dependencias reales del proyecto.

10.3 Prettier

Instálalo localmente para que el proyecto no dependa solo de la extensión de VS Code:

npm install --save-dev prettier

Agrega estos comandos a la sección scripts de package.json sin borrar los existentes:

{
  "scripts": {
    "format": "prettier --write .",
    "format:check": "prettier --check ."
  }
}

Ejecuta:

npm run format
npm run format:check

11 Pruebas con Vitest

Para practicar pruebas sin introducir todavía un navegador simulado, extrae una función pura.

Crea src/utils/quality.ts:

export type QualityLevel = "high" | "acceptable" | "review";

export function classifyQuality(value: number): QualityLevel {
  if (value < 0 || value > 100) {
    throw new RangeError("La calidad debe estar entre 0 y 100");
  }

  if (value >= 90) return "high";
  if (value >= 80) return "acceptable";
  return "review";
}

13 Errores frecuentes y cómo razonarlos

13.1 “Cannot find module…”

Comprueba, en este orden:

  1. que el archivo exista;
  2. que la ruta relativa sea correcta;
  3. que las mayúsculas coincidan exactamente en Linux;
  4. que hayas ejecutado npm install;
  5. que el símbolo se exporte y se importe con el mismo tipo de exportación.
// Exportación nombrada
export function SignalCard() {}
import { SignalCard } from "./SignalCard";

// Exportación por defecto
export default function App() {}
import App from "./App";

13.2 “Type … is not assignable to type …”

No conviertas inmediatamente con as ni uses any. Lee el tipo esperado y el recibido. Corrige el modelo, valida la entrada o aplica una guarda de tipos, como isFilter.

13.3 La interfaz no cambia después de modificar un objeto

Evita mutar estado:

// Incorrecto
signal.reviewed = true;

// Correcto
const updated = { ...signal, reviewed: true };

13.4 Un Hook se ejecuta condicionalmente

Esto es incorrecto:

if (visible) {
  const [filter, setFilter] = useState("ALL");
}

Los Hooks deben ejecutarse siempre en el mismo orden. Decláralos al comienzo del componente.

13.5 La página queda en blanco

Revisa:

  • la consola del navegador (F12);
  • la terminal donde corre Vite;
  • que src/main.tsx monte <App /> en el elemento #root;
  • que no hayas borrado <div id="root"></div> de index.html.

14 Integración con un sitio Quarto

Este tutorial está diseñado como una página, no como un proyecto Quarto independiente. Por eso no incluye un _quarto.yml propio ni fija un tema: al copiar el .qmd dentro de tu sitio, hereda navegación, tema, tipografías y recursos globales.

Un flujo seguro es:

  1. Copia tutorial-react-typescript-vite.qmd a una carpeta como tutoriales/.
  2. Agrega una entrada a la navegación existente; no reemplaces el bloque completo.
  3. Desde la raíz del sitio ejecuta quarto preview.
  4. Comprueba vínculos, tabla de contenido, diagramas Mermaid y bloques de código.

Ejemplo mínimo para integrar en una navegación existente:

website:
  navbar:
    left:
      - href: tutoriales/tutorial-react-typescript-vite.qmd
        text: React, TypeScript y Vite
AdvertenciaQuarto y Vite generan productos distintos

Quarto renderiza este material educativo. Vite compila la aplicación React. No copies node_modules al sitio ni intentes hacer que Quarto lo renderice. Si publicas la aplicación, usa el contenido de dist/ en una ruta separada o un despliegue independiente.
