Tutorial: kitty + Fira Code + Starship para Python en Garuda Linux

Tema oscuro BioForge, prompt con Python, Git y cuenta de GitHub, y monitoreo rápido de tokens

Autor/a

Ph.D. Pablo Eduardo Caicedo-Rodríguez

Fecha de publicación

26 de septiembre de 2026

1 Objetivo

Este tutorial configura un terminal de escritorio para desarrollo en Python en Garuda Linux con:

  • kitty (0.49 o posterior, desde el repositorio extra de Arch) como emulador de terminal.
  • FiraCode Nerd Font Mono tamaño 12.
  • Tema oscuro armónico: fondo casi negro, acentos verdes, naranjas, azules y cian.
  • fish como shell (la de Garuda por defecto), con bash como alternativa.
  • Starship como prompt.
  • Indicadores de Git, Python, entorno virtual (uv) y cuenta de GitHub.
  • Monitoreo rápido de tokens gastados por asistentes de IA para programar (Claude Code, Codex, Gemini CLI y otros), al estilo de YapCap.
  • Comandos de verificación y reversión.

Qué trae Garuda de fábrica (verificado en los paquetes oficiales de Garuda):
fish como shell por defecto, configurado por el paquete garuda-fish-config.
starship ya instalado y ya activado en fish y en bash (paquetes garuda-fish-config, garuda-bash-config y garuda-starship-prompt).
Un ~/.config/starship.toml propio de Garuda, copiado desde /etc/skel/.config/starship.toml.
~/.local/bin ya se agrega al PATH en fish.

2 Qué cambia respecto a la versión Ubuntu/Pop!_OS

Tema Ubuntu / Pop!_OS Garuda Linux
Gestor de paquetes apt pacman (y garuda-update para actualizar todo)
Instalar Starship Instalador install.sh en /usr/local/bin porque APT no tenía el paquete sudo pacman -S starship (ya viene instalado)
Activar Starship Agregar eval "$(starship init bash)" a ~/.bashrc Ya está activado. No se agrega otra línea init
Shell bash fish (bash sigue disponible)
Fuente Fira Code instalada a mano ttf-fira-code y ttf-firacode-nerd desde extra
GitHub CLI Repositorio APT de GitHub con llave GPG sudo pacman -S github-cli
Sesión gráfica X11 Normalmente Wayland (KDE Plasma 6)

Además se corrigieron cuatro detalles de la versión anterior:

  1. kitty.conf usaba FiraCode Nerd Font Mono, pero la verificación buscaba Fira Code. Ahora se instala y se verifica la misma fuente que usa kitty.
  2. El prompt mostraba venv: aunque no hubiera entorno activo. Ahora solo aparece con un entorno activado.
  3. El módulo de GitHub ejecutaba gh auth status dos veces en cada prompt, y ese comando consulta la red. Ahora lee la configuración local de gh y responde en milisegundos.
  4. La clase CSS t-muted del ejemplo visual no estaba definida.

Referencias oficiales:

  • Configuración de Starship (~/.config/starship.toml, módulos python y custom, paletas): https://starship.rs/config/.
  • Activación de Starship en fish y bash: https://starship.rs/#quick-install.
  • Opciones de kitty.conf (font_family, font_size, enabled_layouts, etc.): https://sw.kovidgoyal.net/kitty/conf/.
  • Divisiones de ventana en kitty (launch --location=hsplit): https://sw.kovidgoyal.net/kitty/layouts/.
  • Configuración de fish de Garuda: https://gitlab.com/garuda-linux/pkgbuilds/-/tree/main/garuda-fish-config.
  • Paquetes de Arch: kitty, starship, ttf-fira-code, ttf-firacode-nerd, github-cli.
  • GitHub CLI se autentica con gh auth login: https://docs.github.com/en/github-cli/github-cli/quickstart.
  • Línea de estado de Claude Code (statusLine, rate_limits): https://code.claude.com/docs/en/statusline.

3 Convención de riesgo

Durante el tutorial se usan estas categorías:

Categoría Significado
Inspección No modifica el sistema. Solo muestra información.
Modificación reversible Cambia archivos de configuración del usuario o instala paquetes normales. Se puede revertir.
Modificación delicada Cambia paquetes del sistema o archivos fuera de tu carpeta personal. Requiere más cuidado.
Alto riesgo No se usa en este tutorial. Evitamos borrados recursivos, particiones, arranque y permisos masivos.

Red de seguridad de Garuda: garuda-update y pacman crean un snapshot Btrfs antes de cada transacción. Si una instalación rompe algo, se puede arrancar desde un snapshot anterior en el menú de GRUB y restaurarlo con Btrfs Assistant.

4 Paso 1: inspección segura

Tipo: inspección.

Ejecuta (funciona igual en fish y en bash):

echo $SHELL
echo $XDG_SESSION_TYPE
kitty --version
fc-list | grep -i "FiraCode Nerd Font Mono" | head -3
echo $TERM
starship --version
pacman -Q kitty starship ttf-fira-code ttf-firacode-nerd github-cli

Qué valida cada comando:

Comando Qué verifica
echo $SHELL Qué shell usas. En Garuda suele ser /usr/bin/fish.
echo $XDG_SESSION_TYPE Indica si estás en wayland o x11.
kitty --version Confirma que kitty está instalado y su versión.
fc-list \| grep ... Confirma que fontconfig encuentra la fuente que usará kitty.
echo $TERM Dentro de kitty debe mostrar xterm-kitty.
starship --version Confirma que Starship ya viene instalado.
pacman -Q ... Lista qué paquetes ya están instalados; los que falten aparecen como error: package ... was not found.

Resultado esperado parecido:

/usr/bin/fish
wayland
kitty 0.49.1 created by Kovid Goyal
/usr/share/fonts/TTF/FiraCodeNerdFontMono-Regular.ttf: FiraCode Nerd Font Mono:style=Regular
xterm-kitty
starship 1.26.0
kitty 0.49.1-1
starship 1.26.0-1
...

Las versiones pueden ser más nuevas: Garuda es rolling release y cada garuda-update las actualiza.

Nota Wayland: Garuda con KDE Plasma 6 inicia normalmente en Wayland, y kitty funciona de forma nativa en Wayland. Si ves x11, elegiste una sesión X11 en el gestor de inicio de sesión. Con tarjetas NVIDIA, Wayland depende del controlador instalado (ver el tutorial de instalación de Python y R en Garuda).

5 Paso 2: instalar kitty y las fuentes

Tipo: modificación reversible.

Actualiza primero el sistema completo. En Arch no se recomienda instalar paquetes sobre una base de datos desactualizada:

garuda-update

Instala kitty, Fira Code y su versión Nerd Font:

sudo pacman -S --needed kitty ttf-fira-code ttf-firacode-nerd

Qué hace:

  • --needed omite los paquetes que ya estén instalados.
  • ttf-fira-code es la Fira Code original, con ligaduras.
  • ttf-firacode-nerd es Fira Code con los íconos de Nerd Fonts, que Starship y otros programas de terminal usan para símbolos.

Refresca la caché de fuentes y verifica:

fc-cache -f
fc-list | grep -i "FiraCode Nerd Font Mono" | head -3

6 Paso 3: configurar kitty

6.1 3.1 Crear respaldo

Tipo: modificación reversible.

mkdir -p ~/.config/kitty
cp ~/.config/kitty/kitty.conf ~/.config/kitty/kitty.conf.bak 2>/dev/null || true

Qué hace:

  • mkdir -p ~/.config/kitty crea el directorio si no existe.
  • cp ... .bak crea un respaldo si ya existía kitty.conf.
  • 2>/dev/null || true evita un error visible si el archivo aún no existía. Funciona igual en fish y en bash.

6.2 3.2 Editar kitty.conf

nano ~/.config/kitty/kitty.conf

Si nano no está instalado, usa sudo pacman -S nano, o abre el archivo con micro o con Kate.

Elegir la fuente con vista previa: kitty trae kitten choose-fonts, que muestra las fuentes instaladas con vista previa y escribe la línea font_family por ti.

6.3 3.3 Verificar kitty

echo $TERM

Resultado esperado: xterm-kitty.

Para ver la configuración que kitty cargó realmente, pulsa Ctrl+Shift+F6 dentro de kitty: abre un informe donde deben aparecer FiraCode Nerd Font Mono y tus cambios frente a los valores por defecto.

6.4 3.4 (Opcional) kitty como terminal predeterminado de KDE

En Configuración del sistema → Aplicaciones predeterminadas → Emulador de terminal, elige kitty. Así, las acciones de KDE que abren una terminal (por ejemplo, desde Dolphin) usan kitty.

7 Paso 4: Starship en Garuda (ya instalado)

7.1 4.1 Verificar

Tipo: inspección.

command -v starship
starship --version
pacman -Qi starship | grep -E "^(Name|Version|Required By)"

Resultado esperado:

/usr/bin/starship
starship 1.26.0
Name            : starship
Version         : 1.26.0-1
Required By     : garuda-starship-prompt ...

Si starship no apareciera (por ejemplo, en una instalación mínima):

Tipo: modificación reversible.

sudo pacman -S starship

No uses el instalador install.sh en Garuda. Instalaría una segunda copia en /usr/local/bin que pacman no actualiza, y la configuración de Garuda llama a /usr/bin/starship. Con pacman, Starship se actualiza con cada garuda-update.

7.2 4.2 Dónde se activa

Tipo: inspección.

Garuda ya activa Starship en ambas shells. Compruébalo:

grep -n starship /usr/share/garuda/garuda-fish-config/config.fish
grep -n starship /usr/share/garuda/garuda-bash-config/bashrc

La salida muestra la línea starship init fish (en fish) y starship init bash (en bash). Por eso no hay que agregar eval "$(starship init bash)" como en Ubuntu: una segunda activación duplica el trabajo en cada prompt.

No edites los archivos de /usr/share/garuda/: se sobrescriben en cada actualización. Tus cambios de fish van en ~/.config/fish/config.fish, debajo de la línea # – Insert customizations below this line! –.

8 Paso 5: configurar Starship

8.1 5.1 Crear respaldo

Tipo: modificación reversible.

Garuda ya dejó su propio ~/.config/starship.toml, así que el respaldo sí importa:

mkdir -p ~/.config
cp ~/.config/starship.toml ~/.config/starship.toml.bak 2>/dev/null || true

8.2 5.2 Crear starship.toml

Vacía el archivo de Garuda (ya tienes el respaldo) y ábrelo:

truncate -s 0 ~/.config/starship.toml
nano ~/.config/starship.toml

Pega esto:

# ============================================================
# Starship prompt - BioForge Dark (Garuda Linux)
# Ajustado para:
# - fish (por defecto en Garuda) y bash
# - Python con entornos uv (.venv)
# - Git
# - FiraCode Nerd Font Mono
# - GitHub CLI opcional
# ============================================================

"$schema" = 'https://starship.rs/config-schema.json'

add_newline = true
command_timeout = 800

format = """
$username\
$hostname\
$directory\
$git_branch\
$git_status\
$python\
${custom.github}\
$cmd_duration\
$line_break\
$character
"""

palette = "bioforge"

# Los nombres green, blue, etc. de esta paleta reemplazan
# a los colores estándar en todos los estilos.
[palettes.bioforge]
bg = "#05070a"
fg = "#d7dde5"
gray = "#7f8790"
green = "#9ece6a"
orange = "#e0af68"
yellow = "#f6c177"
blue = "#7aa2f7"
cyan = "#7dcfff"
magenta = "#bb9af7"
red = "#f7768e"

[username]
show_always = true
style_user = "bold green"
style_root = "bold red"
format = "[$user]($style)"

[hostname]
ssh_only = false
style = "bold gray"
format = "[@$hostname]($style) "

[directory]
style = "bold orange"
format = "[$path]($style) "
truncate_to_repo = false
truncation_length = 5
home_symbol = "~"

[git_branch]
symbol = "git:"
style = "bold blue"
format = "[$symbol$branch]($style) "

[git_status]
style = "bold yellow"
format = "([\\[$all_status$ahead_behind\\]]($style) )"

[python]
symbol = "py:"
style = "bold yellow"
version_format = "${major}.${minor}"
# El grupo entre paréntesis hace que "venv:" solo aparezca con un entorno activo.
format = "[$symbol$version]($style) ([venv:$virtualenv](bold magenta) )"
# uv crea el entorno como .venv: en su lugar se muestra el nombre de la carpeta del proyecto.
generic_venv_names = [".venv", "venv"]
detect_extensions = ["py", "ipynb"]
detect_files = ["pyproject.toml", "requirements.txt", "setup.py", "environment.yml", ".python-version", "uv.lock"]
detect_folders = [".venv", "venv"]

# Muestra la cuenta de GitHub activa en GitHub CLI.
# Lee la configuración local de gh (no consulta la red), así el prompt no se frena.
# Solo aparece dentro de repositorios Git.
[custom.github]
description = "Cuenta activa de GitHub"
command = "gh config get -h github.com user"
when = "command -v gh"
require_repo = true
shell = ["sh"]
symbol = "gh:"
style = "bold blue"
format = "[$symbol$output]($style) "

[cmd_duration]
min_time = 700
style = "bold cyan"
format = "[took:$duration]($style) "

[character]
success_symbol = "[❯](bold green)"
error_symbol = "[❯](bold red)"

Qué cambió frente a la versión Ubuntu:

  • version_format muestra py:3.12 en lugar de py:v3.12.7.
  • generic_venv_names hace que un entorno .venv creado con uv aparezca como venv:bioforge (el nombre del proyecto) y no como venv:.venv.
  • custom.github usa require_repo = true (opción oficial de Starship) en lugar de llamar a git rev-parse, y shell = ["sh"] para que el comando se ejecute igual desde fish o desde bash.
  • La línea "$schema" permite que editores como VS Code autocompleten y validen el archivo.

Privacidad: mostrar cuentas en el prompt es cómodo, pero puede exponer tu usuario en capturas de pantalla, clases, videos o documentación. Esta configuración muestra el usuario de GitHub, no el correo, y solo dentro de repositorios Git.

9 Paso 6: aplicar los cambios

Tipo: inspección.

Starship relee starship.toml cada vez que dibuja el prompt, así que no hace falta recargar la shell: basta con pulsar Enter.

Para comprobar que el archivo no tiene errores:

starship print-config > /dev/null

Si no imprime nada, el archivo es válido. Si hay un error, Starship muestra [ERROR] ... Unable to parse the config file con la línea y la columna del problema.

Si alguna vez cambias ~/.config/fish/config.fish, recarga fish con:

exec fish

En bash, el equivalente es source ~/.bashrc.

12 Paso 9: monitoreo rápido de tokens (estilo YapCap)

12.1 9.1 Qué es YapCap y por qué aquí se usa otra cosa

YapCap es un applet para el panel del escritorio COSMIC (el de Pop!_OS) que muestra el uso de cuota de asistentes de IA para programar (Codex, Claude Code, Cursor, Gemini, Copilot…): porcentaje usado de la ventana de 5 horas, de la semana y créditos. Según su propio README, es solo para COSMIC: no tiene versión para KDE, GNOME ni bandeja del sistema, y tampoco tiene modo de terminal. Sus paquetes oficiales son Flatpak (tienda de COSMIC), .deb y .rpm.

En Garuda (KDE Plasma) se reproduce la misma idea con dos piezas de terminal:

Pieza Qué muestra De dónde saca los datos
Línea de estado de Claude Code % usado del límite de 5 h y del límite semanal, % de contexto y costo estimado de la sesión, siempre visible mientras trabajas Los datos que Claude Code recibe de la API (campo rate_limits)
ccusage + función tokens + atajo de kitty Tokens y costo estimado de hoy, bloque de 5 h activo, historial por día/semana/mes Los registros locales de Claude Code, Codex, Gemini CLI, Copilot CLI, OpenCode y otros

Supuesto: “tokens gastados” se refiere a los asistentes de IA para programar que se usan desde la terminal, en particular Claude Code. Los costos que muestran ccusage y Claude Code son estimaciones a precio de lista: con un plan Pro o Max no son lo que pagas, pero sirven para comparar el consumo entre días y proyectos.

12.2 9.2 Instalar las dependencias

Tipo: modificación reversible.

sudo pacman -S --needed jq npm
  • jq procesa el JSON que envía Claude Code a la línea de estado.
  • npm (arrastra nodejs) instala ccusage.

Instala ccusage en tu carpeta personal, sin sudo:

npm install -g --prefix ~/.local ccusage

Qué hace:

  • --prefix ~/.local deja el ejecutable en ~/.local/bin/ccusage, que la configuración de fish de Garuda ya pone en el PATH. No toca archivos del sistema.
  • ccusage trae un binario nativo para Linux x86_64, así que responde en alrededor de un segundo.

Verifica:

ccusage --version
ccusage daily --last 1

Si prefieres no instalar nada, npx ccusage@latest daily --last 1 lo ejecuta sin instalar (más lento, porque descarga el paquete la primera vez).

12.3 9.3 Línea de estado de Claude Code (lo más parecido a YapCap)

Tipo: modificación reversible.

Claude Code puede ejecutar un script después de cada respuesta y mostrar lo que imprima en una barra fija al pie. Ese script recibe un JSON con, entre otros, rate_limits.five_hour.used_percentage y rate_limits.seven_day.used_percentage: los mismos porcentajes que muestra YapCap.

Crea el script:

mkdir -p ~/.claude
nano ~/.claude/statusline.sh

Pega esto:

#!/usr/bin/env bash
# ~/.claude/statusline.sh
# Barra de estado de Claude Code estilo yapcap:
# modelo · contexto · límite de 5 h · límite semanal · costo estimado de la sesión
input=$(cat)

j() { jq -r "$1 // empty" <<<"$input"; }

model=$(j '.model.display_name')
ctx=$(j '.context_window.used_percentage')
h5=$(j '.rate_limits.five_hour.used_percentage')
h5_reset=$(j '.rate_limits.five_hour.resets_at')
d7=$(j '.rate_limits.seven_day.used_percentage')
cost=$(j '.cost.total_cost_usd')

# Colores BioForge (verde < 50 %, naranja < 80 %, rojo >= 80 %)
color() {
  local p=${1%.*}
  if   [ "$p" -ge 80 ]; then printf '\033[1;38;2;247;118;142m'
  elif [ "$p" -ge 50 ]; then printf '\033[1;38;2;224;175;104m'
  else                       printf '\033[1;38;2;158;206;106m'
  fi
}
reset=$'\033[0m'

# Barra de 10 bloques
bar() {
  local p=${1%.*} n i out=""
  n=$(( (p + 5) / 10 )); [ "$n" -gt 10 ] && n=10
  for ((i = 0; i < 10; i++)); do
    if [ "$i" -lt "$n" ]; then out+="▰"; else out+="▱"; fi
  done
  printf '%s' "$out"
}

line="[${model:-?}]"
[ -n "$ctx" ] && line+=" ctx:$(color "$ctx")${ctx%.*}%${reset}"
if [ -n "$h5" ]; then
  line+=" 5h:$(color "$h5")$(bar "$h5") ${h5%.*}%${reset}"
  [ -n "$h5_reset" ] && line+=" ↻$(date -d "@$h5_reset" +%H:%M)"
fi
[ -n "$d7" ] && line+=" 7d:$(color "$d7")$(bar "$d7") ${d7%.*}%${reset}"
[ -n "$cost" ] && line+=" \$$(printf '%.2f' "$cost")"

printf '%s\n' "$line"

Dale permiso de ejecución y pruébalo con datos de ejemplo:

echo '{"model":{"display_name":"Opus"},"context_window":{"used_percentage":8},"cost":{"total_cost_usd":0.01234},"rate_limits":{"five_hour":{"used_percentage":23.5,"resets_at":1738425600},"seven_day":{"used_percentage":81.2}}}' | ~/.claude/statusline.sh

Ahora registra el script en la configuración de usuario de Claude Code, ~/.claude/settings.json. Si el archivo ya existe, este comando agrega la clave statusLine sin borrar el resto; primero hace un respaldo:

12.4 9.4 Función tokens para fish

Tipo: modificación reversible.

fish carga automáticamente las funciones guardadas en ~/.config/fish/functions/, una por archivo:

mkdir -p ~/.config/fish/functions
nano ~/.config/fish/functions/tokens.fish

Pega esto:

# ~/.config/fish/functions/tokens.fish
# Monitoreo rápido de tokens gastados por asistentes de IA (vía ccusage).
#   tokens            -> resumen de hoy + bloque de 5 h activo de Claude Code
#   tokens --line     -> una sola línea: tokens y costo estimado de hoy
#   tokens --watch N  -> panel que se refresca cada N segundos (60 por defecto)
function tokens --description 'Resumen rápido de tokens gastados hoy (ccusage)'
    if not command -q ccusage
        echo "ccusage no está instalado (ver el paso de monitoreo de tokens)." >&2
        return 1
    end

    switch "$argv[1]"
        case --line -l
            ccusage daily --last 1 --json \
                | jq -r '"hoy: \(.totals.totalTokens // 0) tokens (in \(.totals.inputTokens // 0) · out \(.totals.outputTokens // 0)) · $\((.totals.totalCost // 0) * 100 | round / 100)"'
        case --watch -w
            set -l intervalo 60
            if test -n "$argv[2]"
                set intervalo $argv[2]
            end
            while true
                clear
                date '+%F %T'
                ccusage daily --last 1 --compact
                ccusage blocks --active --compact
                echo
                echo "Actualiza cada $intervalo s · Ctrl+C para salir"
                sleep $intervalo
            end
        case '*'
            ccusage daily --last 1 --compact
            ccusage blocks --active --compact
    end
end

Úsala en cualquier ventana nueva de fish:

tokens           # tabla de hoy por agente y modelo + bloque de 5 h activo
tokens --line    # hoy: 27000 tokens (in 1200 · out 800) · $0.04
tokens --watch   # panel que se refresca cada 60 s

totalTokens incluye los tokens leídos de caché, que suelen ser la mayor parte; in y out son los de entrada y salida sin caché.

Alternativa en bash

Agrega esta función al final de ~/.bashrc y ejecuta source ~/.bashrc:

# Monitoreo rápido de tokens (ccusage) - versión bash
tokens() {
  command -v ccusage >/dev/null || { echo "ccusage no está instalado." >&2; return 1; }
  case "$1" in
    --line|-l)
      ccusage daily --last 1 --json \
        | jq -r '"hoy: \(.totals.totalTokens // 0) tokens (in \(.totals.inputTokens // 0) · out \(.totals.outputTokens // 0)) · $\((.totals.totalCost // 0) * 100 | round / 100)"' ;;
    --watch|-w)
      local intervalo=${2:-60}
      while true; do
        clear; date '+%F %T'
        ccusage daily --last 1 --compact
        ccusage blocks --active --compact
        echo; echo "Actualiza cada $intervalo s · Ctrl+C para salir"
        sleep "$intervalo"
      done ;;
    *)
      ccusage daily --last 1 --compact
      ccusage blocks --active --compact ;;
  esac
}

Si usas bash, verifica que ~/.local/bin esté en el PATH (echo $PATH) y cambia el atajo de kitty del Paso 3 por:

map ctrl+shift+u launch --location=hsplit --bias=35 --title=tokens bash -ic "tokens --watch 60"

fish_config prompt choose default carga el prompt de ejemplo default de fish en lugar del de Starship. Para volver a Starship, borra esas dos líneas y ejecuta exec fish.
