Configuración de varias cuentas de Git y GitHub en Linux

Uso seguro de dos o tres identidades mediante SSH

Autor/a

Ph.D. Pablo Eduardo Caicedo R.

Introducción

Es frecuente utilizar varias cuentas de GitHub desde un mismo computador. Por ejemplo, puede existir una cuenta personal, una cuenta institucional o laboral y una tercera cuenta destinada a proyectos académicos.

Aunque Git y GitHub suelen utilizarse juntos, cumplen funciones diferentes:

  • Git registra el nombre y el correo del autor de cada cambio.
  • GitHub determina qué cuenta tiene permiso para acceder a un repositorio.
  • SSH permite seleccionar de forma segura qué cuenta debe utilizarse en cada conexión con GitHub.

Por esta razón, una configuración completa debe resolver dos aspectos:

  • La identidad registrada en los commits.
  • La autenticación utilizada para acceder a GitHub.

En este tutorial se configurarán tres perfiles:

Perfil Carpeta local Alias SSH
Personal ~/GitHub/personal/ github-personal
Trabajo ~/GitHub/trabajo/ github-trabajo
Academia ~/GitHub/academia/ github-academia

La tercera cuenta es opcional. Si solamente se necesitan dos cuentas, pueden omitirse los bloques relacionados con el perfil académico.

En resumen,

Esquema de conexión con GitHub mediante SSH

El acceso a GitHub se realiza mediante un alias SSH asociado con una clave específica. Git utiliza la carpeta del repositorio para seleccionar el nombre y el correo del autor, mientras que SSH selecciona la cuenta utilizada para autenticarse en GitHub.

  1. La ubicación del repositorio determina la identidad del commit.
  2. La dirección del remoto determina el alias SSH.
  3. El alias SSH selecciona una clave privada.
  4. GitHub identifica la cuenta asociada con la clave pública.
Importante

Reemplace los nombres, correos electrónicos, usuarios, organizaciones y nombres de repositorios utilizados en los ejemplos por sus datos reales.

Requisitos previos

Para realizar la configuración se necesita:

  • Una distribución Linux.
  • Dos o tres cuentas de GitHub.
  • Acceso a una terminal.
  • Git instalado.
  • OpenSSH instalado.
  • Un correo electrónico verificado en cada cuenta de GitHub.

Instalar Git y OpenSSH

Los comandos dependen de la distribución Linux utilizada.

  • Ubuntu, Debian, Linux Mint y Pop!_OS
  • Fedora
  • Arch Linux y Manjaro
sudo apt update
sudo apt install -y git openssh-client
sudo dnf install -y git openssh-clients
sudo pacman -Syu git openssh

Comprobar que Git está instalado:

git --version

Comprobar que SSH está instalado:

ssh -V

La versión de OpenSSH puede aparecer en la salida estándar de error. Esto es normal y no indica que exista un problema.

Definir las cuentas

Para cada cuenta se necesita registrar la siguiente información:

Dato Ejemplo
Nombre para los commits Nombre Apellido
Correo verificado usuario@dominio.com
Usuario de GitHub nombre-usuario
Organización, si aplica nombre-organizacion

Un ejemplo de configuración puede ser:

Cuenta Usuario de GitHub Correo
Personal usuario-personal personal@ejemplo.com
Trabajo usuario-trabajo nombre@empresa.com
Academia usuario-academico nombre@universidad.edu

Los nombres utilizados en los commits pueden ser iguales en varias cuentas. El correo electrónico es el dato utilizado por GitHub para asociar un commit con una cuenta.

Puede utilizarse:

  • Un correo verificado en la cuenta.
  • El correo privado proporcionado por GitHub.

El correo privado puede consultarse en:

GitHub → Settings → Emails

Crear las carpetas de trabajo

Se recomienda separar físicamente los repositorios de cada cuenta. Esta estructura también permitirá que Git seleccione automáticamente el nombre y el correo correspondientes.

Crear las carpetas:

mkdir -p ~/GitHub/personal
mkdir -p ~/GitHub/trabajo
mkdir -p ~/GitHub/academia

Comprobar la estructura:

find ~/GitHub -maxdepth 1 -type d

La salida será similar a:

/home/usuario/GitHub
/home/usuario/GitHub/personal
/home/usuario/GitHub/trabajo
/home/usuario/GitHub/academia
Nota

Linux diferencia entre mayúsculas y minúsculas. Las rutas ~/GitHub/ y ~/github/ son diferentes.

Revisar las claves SSH existentes

Crear la carpeta SSH si todavía no existe:

mkdir -p ~/.ssh
chmod 700 ~/.ssh

Listar su contenido:

ls -la ~/.ssh

Pueden aparecer archivos como:

id_ed25519
id_ed25519.pub
id_rsa
id_rsa.pub
known_hosts
config

No elimine claves existentes sin comprobar previamente dónde se utilizan.

Crear una clave SSH para cada cuenta

Cada cuenta debe utilizar una clave SSH diferente. Se utilizará el algoritmo Ed25519.

Cuenta personal

ssh-keygen \
  -t ed25519 \
  -C "CORREO_PERSONAL" \
  -f ~/.ssh/id_ed25519_github_personal

Ejemplo:

ssh-keygen \
  -t ed25519 \
  -C "personal@ejemplo.com" \
  -f ~/.ssh/id_ed25519_github_personal

Cuenta de trabajo

ssh-keygen \
  -t ed25519 \
  -C "CORREO_TRABAJO" \
  -f ~/.ssh/id_ed25519_github_trabajo

Ejemplo:

ssh-keygen \
  -t ed25519 \
  -C "nombre@empresa.com" \
  -f ~/.ssh/id_ed25519_github_trabajo

Cuenta académica

Este paso solamente es necesario cuando se utilizará una tercera cuenta.

ssh-keygen \
  -t ed25519 \
  -C "CORREO_ACADEMICO" \
  -f ~/.ssh/id_ed25519_github_academia

Ejemplo:

ssh-keygen \
  -t ed25519 \
  -C "nombre@universidad.edu" \
  -f ~/.ssh/id_ed25519_github_academia

Durante la generación de cada clave, SSH solicitará una frase de contraseña:

Enter passphrase (empty for no passphrase):

Se recomienda establecer una frase de contraseña. Esta frase protege la clave privada en caso de que otra persona obtenga acceso al computador.

Después de crear las claves, la carpeta ~/.ssh contendrá archivos similares a los siguientes:

id_ed25519_github_personal
id_ed25519_github_personal.pub
id_ed25519_github_trabajo
id_ed25519_github_trabajo.pub
id_ed25519_github_academia
id_ed25519_github_academia.pub

Los archivos sin extensión son claves privadas. Nunca deben:

  • Publicarse.
  • Enviarse por correo electrónico.
  • Copiarse en servicios de mensajería.
  • Agregarse a repositorios.
  • Compartirse con otras personas.

Los archivos terminados en .pub son las claves públicas que se registrarán en GitHub.

Configurar los permisos de las claves

Asignar permisos restrictivos a las claves privadas:

chmod 600 ~/.ssh/id_ed25519_github_personal
chmod 600 ~/.ssh/id_ed25519_github_trabajo
chmod 600 ~/.ssh/id_ed25519_github_academia

Asignar permisos de lectura a las claves públicas:

chmod 644 ~/.ssh/id_ed25519_github_personal.pub
chmod 644 ~/.ssh/id_ed25519_github_trabajo.pub
chmod 644 ~/.ssh/id_ed25519_github_academia.pub

Cuando solo se utilizan dos cuentas, debe omitirse la línea correspondiente a la cuenta académica.

Registrar las claves públicas en GitHub

Cada clave pública debe registrarse únicamente en la cuenta correspondiente.

Registrar la clave personal

Mostrar la clave pública:

cat ~/.ssh/id_ed25519_github_personal.pub

La salida tendrá una estructura similar a:

ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... personal@ejemplo.com

Copiar toda la línea.

Ingresar a la cuenta personal de GitHub y abrir:

Settings → SSH and GPG keys → New SSH key

Utilizar un título descriptivo:

Computador Linux personal

Seleccionar el tipo:

Authentication Key

Pegar la clave pública y guardar.

Registrar la clave de trabajo

Mostrar la clave:

cat ~/.ssh/id_ed25519_github_trabajo.pub

Ingresar a la cuenta de trabajo de GitHub y abrir:

Settings → SSH and GPG keys → New SSH key

Utilizar un título como:

Computador Linux trabajo

Pegar la clave pública y guardar.

Registrar la clave académica

Mostrar la clave:

cat ~/.ssh/id_ed25519_github_academia.pub

Ingresar a la cuenta académica y registrar la clave con un título como:

Computador Linux academia
Advertencia

Una misma clave SSH pública no debe reutilizarse en varias cuentas. Cada cuenta debe tener su propia clave.

Iniciar el agente SSH

El agente SSH mantiene las claves disponibles durante la sesión.

Iniciar el agente:

eval "$(ssh-agent -s)"

La salida será similar a:

Agent pid 12345

Agregar la clave personal:

ssh-add ~/.ssh/id_ed25519_github_personal

Agregar la clave de trabajo:

ssh-add ~/.ssh/id_ed25519_github_trabajo

Agregar la clave académica:

ssh-add ~/.ssh/id_ed25519_github_academia

Comprobar las claves cargadas:

ssh-add -l

Cuando solamente se utilizan dos cuentas, debe omitirse el comando de la cuenta académica.

Nota

Entornos de escritorio como GNOME o KDE pueden iniciar automáticamente un agente SSH. En servidores o terminales independientes puede ser necesario iniciarlo manualmente.

Crear los alias SSH

El archivo ~/.ssh/config permite asignar un alias diferente a cada cuenta, aunque todas se conecten realmente a github.com.

Abrir el archivo:

nano ~/.ssh/config

Agregar el siguiente contenido:

Host github-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_github_personal
    IdentitiesOnly yes
    AddKeysToAgent yes

Host github-trabajo
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_github_trabajo
    IdentitiesOnly yes
    AddKeysToAgent yes

Host github-academia
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_github_academia
    IdentitiesOnly yes
    AddKeysToAgent yes

Guardar el archivo en Nano:

Ctrl + O
Enter
Ctrl + X

Asignar los permisos correctos:

chmod 600 ~/.ssh/config

Cuando solamente se utilizan dos cuentas, el archivo puede quedar así:

Host github-personal
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_github_personal
    IdentitiesOnly yes
    AddKeysToAgent yes

Host github-trabajo
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_github_trabajo
    IdentitiesOnly yes
    AddKeysToAgent yes

La opción:

IdentitiesOnly yes

obliga a SSH a utilizar exclusivamente la clave definida en el bloque. Esto evita que SSH pruebe primero una clave perteneciente a otra cuenta.

Comprobar la configuración SSH

Consultar la configuración efectiva del perfil personal:

ssh -G github-personal | grep -E '^(hostname|user|identityfile) '

La salida debe incluir:

hostname github.com
user git
identityfile ~/.ssh/id_ed25519_github_personal

Consultar el perfil de trabajo:

ssh -G github-trabajo | grep -E '^(hostname|user|identityfile) '

Consultar el perfil académico:

ssh -G github-academia | grep -E '^(hostname|user|identityfile) '

Probar las conexiones SSH

Cuenta personal

ssh -T git@github-personal

La respuesta esperada será similar a:

Hi USUARIO_PERSONAL! You've successfully authenticated, but GitHub does not provide shell access.

Cuenta de trabajo

ssh -T git@github-trabajo

La respuesta debe mencionar el usuario de trabajo:

Hi USUARIO_TRABAJO! You've successfully authenticated, but GitHub does not provide shell access.

Cuenta académica

ssh -T git@github-academia

La respuesta debe mencionar el usuario académico:

Hi USUARIO_ACADEMICO! You've successfully authenticated, but GitHub does not provide shell access.

El mensaje indica que la autenticación fue exitosa. GitHub no ofrece acceso a una terminal remota, por lo que la referencia a la ausencia de acceso de shell es normal.

Durante la primera conexión puede aparecer:

Are you sure you want to continue connecting (yes/no/[fingerprint])?

Antes de aceptar, se recomienda comparar la huella digital mostrada con las huellas oficiales publicadas por GitHub.

Revisar la configuración global de Git

Consultar la configuración actual:

git config --global --list

También puede consultarse el archivo de origen de cada valor:

git config --global --list --show-origin

Cuando se manejan varias cuentas, no es recomendable conservar globalmente un único nombre y correo.

Eliminar un nombre global existente:

git config --global --unset-all user.name || true

Eliminar un correo global existente:

git config --global --unset-all user.email || true

Configurar el nombre de la rama inicial:

git config --global init.defaultBranch main

Impedir que Git construya automáticamente una identidad:

git config --global user.useConfigOnly true

Esta opción hace que Git rechace un commit cuando no encuentra una identidad configurada explícitamente. Esto ayuda a evitar commits con el correo equivocado.

Crear los perfiles de identidad de Git

Se utilizará un archivo diferente para cada cuenta.

Perfil personal

Crear el archivo:

nano ~/.gitconfig-personal

Agregar:

[user]
    name = NOMBRE_PERSONAL
    email = CORREO_PERSONAL

Ejemplo:

[user]
    name = Andrea Pérez
    email = personal@ejemplo.com

Perfil de trabajo

Crear el archivo:

nano ~/.gitconfig-trabajo

Agregar:

[user]
    name = NOMBRE_TRABAJO
    email = CORREO_TRABAJO

Ejemplo:

[user]
    name = Andrea Pérez
    email = nombre@empresa.com

Perfil académico

Crear el archivo:

nano ~/.gitconfig-academia

Agregar:

[user]
    name = NOMBRE_ACADEMICO
    email = CORREO_ACADEMICO

Ejemplo:

[user]
    name = Andrea Pérez
    email = nombre@universidad.edu

Seleccionar automáticamente el perfil de Git

Editar el archivo principal de configuración:

nano ~/.gitconfig

Agregar:

[init]
    defaultBranch = main

[user]
    useConfigOnly = true

[includeIf "gitdir:~/GitHub/personal/"]
    path = ~/.gitconfig-personal

[includeIf "gitdir:~/GitHub/trabajo/"]
    path = ~/.gitconfig-trabajo

[includeIf "gitdir:~/GitHub/academia/"]
    path = ~/.gitconfig-academia

Cuando solamente existen dos cuentas, eliminar este bloque:

[includeIf "gitdir:~/GitHub/academia/"]
    path = ~/.gitconfig-academia

La barra final de cada ruta es importante:

gitdir:~/GitHub/personal/

La condición se aplicará a los repositorios ubicados dentro de esa carpeta y de sus subcarpetas.

Comprobar la selección automática

Crear un repositorio temporal para la cuenta personal:

mkdir -p ~/GitHub/personal/prueba-identidad
cd ~/GitHub/personal/prueba-identidad
git init

Consultar el nombre:

git config --get user.name

Consultar el correo:

git config --get user.email

Consultar el origen de la configuración:

git config --show-origin --get user.name
git config --show-origin --get user.email

La salida debe mencionar:

.gitconfig-personal

Probar la cuenta de trabajo:

mkdir -p ~/GitHub/trabajo/prueba-identidad
cd ~/GitHub/trabajo/prueba-identidad
git init

git config --show-origin --get user.name
git config --show-origin --get user.email

La salida debe mencionar:

.gitconfig-trabajo

Probar la cuenta académica:

mkdir -p ~/GitHub/academia/prueba-identidad
cd ~/GitHub/academia/prueba-identidad
git init

git config --show-origin --get user.name
git config --show-origin --get user.email

La salida debe mencionar:

.gitconfig-academia

Eliminar los repositorios de prueba:

rm -rf ~/GitHub/personal/prueba-identidad
rm -rf ~/GitHub/trabajo/prueba-identidad
rm -rf ~/GitHub/academia/prueba-identidad

Clonar repositorios con la cuenta correcta

GitHub muestra normalmente direcciones SSH con este formato:

git@github.com:PROPIETARIO/REPOSITORIO.git

En esta configuración debe reemplazarse github.com por el alias SSH de la cuenta.

Repositorio personal

Cambiar a la carpeta personal:

cd ~/GitHub/personal

Clonar el repositorio:

git clone \
  git@github-personal:USUARIO_PERSONAL/NOMBRE_REPOSITORIO.git

Ejemplo:

git clone git@github-personal:usuario-personal/portafolio.git

Repositorio de trabajo

Cambiar a la carpeta de trabajo:

cd ~/GitHub/trabajo

Clonar un repositorio perteneciente a una organización:

git clone \
  git@github-trabajo:ORGANIZACION_TRABAJO/NOMBRE_REPOSITORIO.git

Ejemplo:

git clone \
  git@github-trabajo:empresa-analitica/modelos-predictivos.git

Repositorio académico

Cambiar a la carpeta académica:

cd ~/GitHub/academia

Clonar el repositorio:

git clone \
  git@github-academia:ORGANIZACION_ACADEMICA/NOMBRE_REPOSITORIO.git

Ejemplo:

git clone \
  git@github-academia:grupo-investigacion/procesamiento-eeg.git

Crear un repositorio personal nuevo

Crear la carpeta:

cd ~/GitHub/personal
mkdir mi-proyecto
cd mi-proyecto

Inicializar Git:

git init

Crear un archivo inicial:

printf "# Mi proyecto\n" > README.md

Crear el primer commit:

git add README.md
git commit -m "Crear estructura inicial"

Después de crear un repositorio vacío en GitHub, asociar el remoto:

git remote add origin \
  git@github-personal:USUARIO_PERSONAL/mi-proyecto.git

Publicar la rama:

git push -u origin main

Crear un repositorio de trabajo nuevo

Crear la carpeta:

cd ~/GitHub/trabajo
mkdir proyecto-empresa
cd proyecto-empresa

Inicializar Git:

git init

Crear un archivo inicial:

printf "# Proyecto de empresa\n" > README.md

Crear el commit:

git add README.md
git commit -m "Crear estructura inicial"

Asociar el remoto:

git remote add origin \
  git@github-trabajo:ORGANIZACION_TRABAJO/proyecto-empresa.git

Publicar:

git push -u origin main

Crear un repositorio académico nuevo

Crear el proyecto:

cd ~/GitHub/academia

git init

printf "# Proyecto de investigación\n" > README.md

Asociar el remoto:

Configurar un repositorio existente

Consultar el remoto actual:

git remote -v

Un repositorio puede tener una dirección como:

git@github.com:ORGANIZACION/REPOSITORIO.git

Esta dirección no indica cuál de las claves configuradas debe utilizarse.

Asignar la cuenta personal

git remote set-url origin \
  git@github-personal:USUARIO_PERSONAL/REPOSITORIO.git

Asignar la cuenta de trabajo

git remote set-url origin \
  git@github-trabajo:ORGANIZACION_TRABAJO/REPOSITORIO.git

Asignar la cuenta académica

git remote set-url origin \
  git@github-academia:ORGANIZACION_ACADEMICA/REPOSITORIO.git

Comprobar el cambio:

git remote -v

Mover un repositorio a la carpeta correcta

Si un repositorio está fuera de las carpetas configuradas, puede moverse al perfil correspondiente.

Por ejemplo, para un proyecto de trabajo:

mv ~/proyectos/mi-proyecto ~/GitHub/trabajo/
cd ~/GitHub/trabajo/mi-proyecto

Comprobar la identidad:

git config --show-origin --get user.name
git config --show-origin --get user.email

Comprobar el remoto:

git remote -v

Corregir el remoto si es necesario:

git remote set-url origin \
  git@github-trabajo:ORGANIZACION_TRABAJO/REPOSITORIO.git

Configurar una identidad específica para un repositorio

Un repositorio puede necesitar una identidad diferente de la configurada para su carpeta.

Dentro del repositorio, ejecutar:

git config --local user.name "NOMBRE ESPECIFICO"
git config --local user.email "CORREO_ESPECIFICO"

Comprobar el resultado:

git config --show-origin --get user.name
git config --show-origin --get user.email

La configuración local se almacena en:

.git/config

La configuración local tiene prioridad sobre los perfiles cargados mediante includeIf.

Eliminar la configuración local:

git config --local --unset-all user.name
git config --local --unset-all user.email

Verificar la identidad antes de crear un commit

Consultar el nombre:

git config --get user.name

Consultar el correo:

git config --get user.email

Consultar el remoto:

git remote -v

Consultar el archivo de origen de la identidad:

git config --show-origin --get user.name
git config --show-origin --get user.email

Un repositorio de trabajo debería mostrar un resultado equivalente a:

Nombre Apellido
nombre@empresa.com
git@github-trabajo:ORGANIZACION_TRABAJO/REPOSITORIO.git

Deben comprobarse dos elementos diferentes:

  • El nombre y correo determinan el autor del commit.
  • El alias SSH del remoto determina la cuenta utilizada para el push.

Crear un alias de diagnóstico

Puede crearse un alias que muestre la identidad y el remoto del repositorio actual.

Ejecutar:

git config --global alias.whoami \
'!f() {
  echo "Nombre:";
  git config --get user.name || echo "No configurado";
  echo;
  echo "Correo:";
  git config --get user.email || echo "No configurado";
  echo;
  echo "Remoto:";
  git remote get-url origin 2>/dev/null || echo "No configurado";
}; f'

Después podrá utilizarse:

git whoami

Una salida posible será:

Nombre:
Andrea Pérez

Correo:
nombre@empresa.com

Remoto:
git@github-trabajo:empresa-analitica/modelos.git

Corregir el último commit

Consultar el autor del último commit:

git log -1 --format='Autor: %an <%ae>'

Cuando el commit todavía no se ha publicado y contiene una identidad incorrecta, configurar la identidad adecuada:

git config user.name "NOMBRE CORRECTO"
git config user.email "CORREO CORRECTO"

Corregir el autor:

git commit --amend --reset-author --no-edit

Comprobar el resultado:

git log -1 --format='Autor: %an <%ae>'
Advertencia

Modificar commits que ya fueron publicados cambia el historial. No se recomienda reescribir una rama compartida sin coordinarlo previamente con las demás personas involucradas.

Solucionar el error Permission denied

El error puede aparecer como:

Permission denied (publickey).

Probar detalladamente la cuenta personal:

ssh -vT git@github-personal

Probar la cuenta de trabajo:

ssh -vT git@github-trabajo

Probar la cuenta académica:

ssh -vT git@github-academia

Revisar las claves cargadas:

ssh-add -l

Agregar nuevamente las claves si no aparecen:

ssh-add ~/.ssh/id_ed25519_github_personal
ssh-add ~/.ssh/id_ed25519_github_trabajo
ssh-add ~/.ssh/id_ed25519_github_academia

Revisar los permisos:

chmod 700 ~/.ssh
chmod 600 ~/.ssh/config
chmod 600 ~/.ssh/id_ed25519_github_personal
chmod 600 ~/.ssh/id_ed25519_github_trabajo
chmod 600 ~/.ssh/id_ed25519_github_academia

También debe comprobarse que cada clave pública esté registrada en la cuenta correcta de GitHub.

Solucionar el uso de una cuenta equivocada

Probar cada alias:

ssh -T git@github-personal
ssh -T git@github-trabajo
ssh -T git@github-academia

Cada comando debe responder con un usuario de GitHub diferente.

Después revisar el remoto del repositorio:

git remote -v

Un repositorio de trabajo no debe utilizar:

git@github-personal:ORGANIZACION/REPOSITORIO.git

Debe utilizar:

git@github-trabajo:ORGANIZACION/REPOSITORIO.git

Corregirlo:

git remote set-url origin \
  git@github-trabajo:ORGANIZACION/REPOSITORIO.git

Solucionar el uso de un correo incorrecto

Consultar todas las configuraciones relacionadas con el nombre:

git config --show-origin --get-all user.name

Consultar todas las configuraciones relacionadas con el correo:

git config --show-origin --get-all user.email

Comprobar si existe una identidad local:

git config --local --list

Eliminar valores locales incorrectos:

git config --local --unset-all user.name
git config --local --unset-all user.email

Comprobar nuevamente:

git config --get user.name
git config --get user.email

Solucionar el error Author identity unknown

Git puede mostrar:

Author identity unknown

Este error indica que el repositorio no está dentro de una carpeta administrada por includeIf y tampoco tiene una identidad local.

Consultar la ubicación:

pwd

Mover el repositorio a la carpeta correspondiente o configurar una identidad local:

git config --local user.name "NOMBRE"
git config --local user.email "CORREO"

Solucionar el error Key already in use

GitHub puede mostrar:

Key already in use

Esto significa que la clave pública ya está registrada en otra cuenta o como clave de despliegue.

La solución recomendada es generar una clave nueva:

ssh-keygen \
  -t ed25519 \
  -C "CORREO_DE_LA_CUENTA" \
  -f ~/.ssh/id_ed25519_github_nueva_cuenta

Después debe registrarse la nueva clave pública en GitHub y crear un bloque adicional en ~/.ssh/config.

Configuración final esperada

La estructura general será similar a:

/home/usuario/
├── .gitconfig
├── .gitconfig-personal
├── .gitconfig-trabajo
├── .gitconfig-academia
├── .ssh/
│   ├── config
│   ├── id_ed25519_github_personal
│   ├── id_ed25519_github_personal.pub
│   ├── id_ed25519_github_trabajo
│   ├── id_ed25519_github_trabajo.pub
│   ├── id_ed25519_github_academia
│   └── id_ed25519_github_academia.pub
└── GitHub/
    ├── personal/
    ├── trabajo/
    └── academia/

El archivo ~/.ssh/config selecciona la clave utilizada para autenticarse.

El archivo ~/.gitconfig selecciona automáticamente el perfil según la carpeta del repositorio.

Los archivos:

~/.gitconfig-personal
~/.gitconfig-trabajo
~/.gitconfig-academia

contienen el nombre y el correo utilizados en los commits.

Lista de comprobación

Antes de trabajar con un repositorio, comprobar:

  • El repositorio está en la carpeta del perfil correcto.
  • git config --get user.name muestra el nombre esperado.
  • git config --get user.email muestra un correo verificado.
  • git remote -v utiliza el alias SSH correcto.
  • ssh -T reconoce la cuenta esperada.
  • Las claves privadas tienen permisos 600.
  • La carpeta ~/.ssh tiene permisos 700.
  • Las claves privadas no están almacenadas en repositorios.

Flujo de trabajo recomendado

Para proyectos personales:

cd ~/GitHub/personal
git clone git@github-personal:USUARIO_PERSONAL/REPOSITORIO.git

Para proyectos de trabajo:

cd ~/GitHub/trabajo
git clone git@github-trabajo:ORGANIZACION_TRABAJO/REPOSITORIO.git

Para proyectos académicos:

cd ~/GitHub/academia
git clone git@github-academia:ORGANIZACION_ACADEMICA/REPOSITORIO.git

Dentro de cada repositorio:

git whoami
git status
git add .
git commit -m "Descripción del cambio"
git push

Esta organización reduce el riesgo de publicar código con la cuenta incorrecta o registrar commits con un correo que no corresponde al proyecto.

quarto render configurar-varias-cuentas-github.qmd

El archivo generado estará disponible en la misma carpeta con el nombre:

configurar-varias-cuentas-github.html

quarto preview configurar-varias-cuentas-github.qmd
