Configuración de uv para gestionar entornos Python

Instalación y uso en Linux y Windows sin permisos de administrador

Autor/a

Ph.D. Pablo Eduardo Caicedo R.

Introducción

uv es un administrador de proyectos, paquetes, versiones de Python y entornos virtuales desarrollado por Astral. Puede reemplazar o complementar herramientas como pip, pip-tools, virtualenv, venv, pipx, Poetry y Pyenv.

Entre sus principales funciones se encuentran:

  • instalar diferentes versiones de Python;
  • crear entornos virtuales aislados;
  • inicializar proyectos Python;
  • declarar y resolver dependencias;
  • generar archivos de bloqueo reproducibles;
  • ejecutar scripts dentro del entorno correcto;
  • instalar herramientas de línea de comandos;
  • administrar una caché compartida de paquetes.

Una ventaja importante es que el instalador autónomo de uv no necesita que Python esté previamente instalado.

NotaObjetivo del tutorial

Al finalizar este tutorial se podrá:

  • instalar uv en Linux;
  • instalar uv en Windows sin una cuenta de administrador;
  • instalar y seleccionar versiones de Python;
  • crear entornos virtuales;
  • iniciar proyectos reproducibles;
  • agregar, actualizar y eliminar dependencias;
  • ejecutar aplicaciones sin activar manualmente el entorno virtual.

Arquitectura general de uv

uv funciona como una capa de administración entre el usuario, las versiones de Python, las dependencias y los archivos del proyecto.

El entorno virtual de cada proyecto se guarda, por defecto, en una carpeta llamada .venv. Esta carpeta se mantiene separada de las instalaciones globales de Python y de los entornos de otros proyectos.

Conceptos fundamentales

Antes de instalar uv, conviene diferenciar los elementos que administra.

Elemento Función
uv Ejecutable que administra Python, proyectos, paquetes y entornos.
Python Intérprete utilizado para ejecutar el código.
.venv/ Entorno virtual aislado del proyecto.
pyproject.toml Configuración y declaración principal de dependencias.
uv.lock Versiones exactas resueltas para obtener instalaciones reproducibles.
.python-version Versión de Python seleccionada para el proyecto.
Caché de uv Almacén compartido que evita descargar repetidamente los mismos paquetes.
ImportanteNo confundir uv con Python

Instalar uv no significa instalar automáticamente todas las versiones de Python. Después de instalarlo, se puede pedir a uv que descargue las versiones necesarias.

Por ejemplo:

uv python install 3.12

Instalación en Linux

Flujo de instalación

Identificar el shell utilizado

En Linux, el instalador puede modificar la configuración del shell para agregar uv al PATH. Para identificar el shell actual, ejecute:

echo "$SHELL"

Los resultados más comunes son:

/bin/bash
/bin/zsh
/usr/bin/fish

También puede consultar el nombre del proceso actual:

ps -p $$ -o comm=

Comprobar curl o wget

Compruebe si curl está disponible:

curl --version

Como alternativa, compruebe wget:

wget --version

Cuando ninguno esté instalado, utilice el administrador de paquetes de la distribución.

Ubuntu, Debian y distribuciones derivadas

sudo apt update
sudo apt install -y curl

Fedora

sudo dnf install -y curl

Arch Linux y distribuciones derivadas

sudo pacman -S curl
Tip

Solo se necesita una de las dos herramientas: curl o wget.

Inspeccionar el instalador

Antes de ejecutar un script descargado desde Internet, es posible revisar su contenido:

curl -LsSf https://astral.sh/uv/install.sh | less

Presione q para salir de less.

También se puede guardar el script en un archivo temporal:

curl -LsSf https://astral.sh/uv/install.sh \
  -o /tmp/install-uv.sh

less /tmp/install-uv.sh

Después de revisarlo:

sh /tmp/install-uv.sh

Instalar uv con curl

El método recomendado por Astral es:

curl -LsSf https://astral.sh/uv/install.sh | sh

El instalador normalmente guarda los ejecutables del usuario en:

~/.local/bin/

Los ejecutables principales son:

uv
uvx

Instalar uv con wget

Cuando curl no esté disponible:

wget -qO- https://astral.sh/uv/install.sh | sh

Recargar la terminal

La opción más sencilla es cerrar la terminal y abrirla nuevamente.

También puede recargarse manualmente la configuración del shell.

Bash

source ~/.bashrc

Zsh

source ~/.zshrc

Verificar la instalación

Ejecute:

uv --version

También puede localizar el ejecutable:

command -v uv

El resultado normalmente será similar a:

/home/usuario/.local/bin/uv

Consulte la ayuda general:

uv --help

Corregir el PATH manualmente

Cuando aparezca el mensaje uv: command not found, agregue el directorio de instalación al PATH.

Bash

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

Zsh

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

Fish

fish_add_path "$HOME/.local/bin"

Compruebe nuevamente:

uv --version

Configurar autocompletado en Bash

echo 'eval "$(uv generate-shell-completion bash)"' \
  >> ~/.bashrc

echo 'eval "$(uvx --generate-shell-completion bash)"' \
  >> ~/.bashrc

source ~/.bashrc

Configurar autocompletado en Zsh

echo 'eval "$(uv generate-shell-completion zsh)"' \
  >> ~/.zshrc

echo 'eval "$(uvx --generate-shell-completion zsh)"' \
  >> ~/.zshrc

source ~/.zshrc

Actualizar uv en Linux

Cuando se utilizó el instalador autónomo oficial:

uv self update

Compruebe la versión instalada:

uv --version

Instalación en Windows sin administrador

La instalación puede realizarse desde una sesión normal de PowerShell. No es necesario abrir PowerShell con la opción Ejecutar como administrador.

El instalador se ejecuta en el contexto del usuario y almacena el ejecutable en un directorio perteneciente a ese usuario.

Flujo de instalación

Abrir PowerShell

Abra el menú Inicio, busque PowerShell y ejecútelo normalmente.

No seleccione:

Ejecutar como administrador

Para comprobar la identidad de la sesión:

whoami

Inspeccionar el instalador

Antes de ejecutarlo, puede revisar su contenido:

powershell -c "irm https://astral.sh/uv/install.ps1 | more"

irm es un alias de Invoke-RestMethod.

Ejecutar el instalador oficial

Ejecute:

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

En este comando:

  • -ExecutionPolicy ByPass aplica la política únicamente al proceso lanzado;
  • irm descarga el script;
  • iex ejecuta el contenido descargado;
  • no se modifica la política de ejecución de todo el computador;
  • no se requiere acceso a la cuenta de administrador.
Advertencia

No cambie la política de ejecución con alcance LocalMachine. Para instalar uv no es necesario modificar la configuración global del equipo.

Cerrar y volver a abrir PowerShell

Después de instalar, cierre todas las ventanas de PowerShell y abra una nueva.

Compruebe la instalación:

uv --version

Localice el comando:

Get-Command uv

Corregir el PATH del usuario

Cuando PowerShell indique que uv no se reconoce como comando, agregue el directorio de instalación al PATH del usuario.

$uvBin = Join-Path $env:USERPROFILE ".local\bin"

$currentUserPath = [Environment]::GetEnvironmentVariable(
    "Path",
    "User"
)

$pathEntries = $currentUserPath -split ";"

if ($pathEntries -notcontains $uvBin) {
    $newUserPath = if ([string]::IsNullOrWhiteSpace($currentUserPath)) {
        $uvBin
    }
    else {
        "$currentUserPath;$uvBin"
    }

    [Environment]::SetEnvironmentVariable(
        "Path",
        $newUserPath,
        "User"
    )
}

Actualice también el PATH de la sesión actual:

$env:Path = "$env:Path;$uvBin"

Verifique:

uv --version
Nota

La modificación anterior afecta solamente el PATH del usuario actual. No modifica el PATH del sistema y no necesita permisos administrativos.

Configurar autocompletado en PowerShell

Compruebe si existe un perfil:

Test-Path $PROFILE

Créelo cuando sea necesario:

if (!(Test-Path -Path $PROFILE)) {
    New-Item -ItemType File -Path $PROFILE -Force
}

Agregue el autocompletado de uv:

Add-Content `
    -Path $PROFILE `
    -Value '(& uv generate-shell-completion powershell) | Out-String | Invoke-Expression'

Agregue el autocompletado de uvx:

Add-Content `
    -Path $PROFILE `
    -Value '(& uvx --generate-shell-completion powershell) | Out-String | Invoke-Expression'

Cierre y abra PowerShell.

Actualizar uv en Windows

Cuando se utilizó el instalador autónomo:

uv self update

Compruebe la versión:

uv --version

Instalar y administrar Python con uv

Después de instalar uv, puede administrar versiones de Python sin depender de una instalación global realizada por un administrador.

Consultar versiones disponibles

uv python list

La lista puede incluir:

  • versiones instaladas por uv;
  • versiones del sistema;
  • versiones disponibles para descargar.

Instalar una versión de Python

Para instalar Python 3.12:

uv python install 3.12

Para instalar varias versiones:

uv python install 3.11 3.12 3.13

Para instalar la versión estable seleccionada por uv:

uv python install

Ver las versiones instaladas por uv

uv python list --only-installed

También puede consultar el directorio donde uv almacena Python:

uv python dir

Seleccionar una versión para un proyecto

Desde la raíz del proyecto:

uv python pin 3.12

Este comando crea o actualiza:

.python-version

Para consultar la selección actual:

uv python pin

Seleccionar una versión global del usuario

uv python pin --global 3.12

La selección local de un proyecto tiene prioridad sobre la configuración global.

Eliminar una versión administrada

uv python uninstall 3.11

Crear un proyecto Python

Flujo de trabajo recomendado

Inicializar un proyecto nuevo

uv init mi-proyecto
cd mi-proyecto

También puede especificar la versión de Python desde el inicio:

uv init --python 3.12 mi-proyecto
cd mi-proyecto

Para inicializar el directorio actual:

mkdir mi-proyecto
cd mi-proyecto
uv init --python 3.12

Estructura inicial

Después de ejecutar uv init, la estructura será similar a:

mi-proyecto/
├── .git/
├── .gitignore
├── .python-version
├── README.md
├── main.py
└── pyproject.toml

Después de ejecutar uv run, uv sync o uv lock, aparecerán otros elementos:

mi-proyecto/
├── .git/
├── .venv/
├── .gitignore
├── .python-version
├── README.md
├── main.py
├── pyproject.toml
└── uv.lock

Ejecutar el programa inicial

uv run main.py

uv run realiza automáticamente las siguientes operaciones:

  1. identifica el proyecto;
  2. comprueba la versión de Python;
  3. crea .venv cuando no existe;
  4. verifica pyproject.toml;
  5. actualiza el archivo de bloqueo cuando sea necesario;
  6. sincroniza las dependencias;
  7. ejecuta el comando dentro del entorno.

Por esta razón, generalmente no es necesario activar manualmente .venv.

Administrar dependencias

Agregar una dependencia

uv add requests

Para agregar varias dependencias:

uv add numpy pandas matplotlib

El comando modifica:

pyproject.toml
uv.lock
.venv/

Agregar una versión específica

uv add "pandas==2.3.0"

También puede utilizar restricciones:

uv add "numpy>=2.0,<3.0"
Tip

En Linux, coloque entre comillas los requisitos que contengan operadores como >, < o *. Esto evita que el shell los interprete.

Agregar dependencias de desarrollo

Las herramientas utilizadas para pruebas, formato o análisis estático pueden agregarse al grupo de desarrollo:

uv add --dev pytest ruff

Otro ejemplo:

uv add --dev mypy coverage

Estas dependencias no se consideran requisitos de ejecución de la aplicación publicada.

Eliminar una dependencia

uv remove matplotlib

Actualizar una dependencia

Para actualizar un paquete específico dentro de sus restricciones:

uv lock --upgrade-package pandas
uv sync

Para intentar actualizar todas las dependencias compatibles:

uv lock --upgrade
uv sync

Mostrar el árbol de dependencias

uv tree

Sincronizar el entorno

uv sync

Este comando hace que .venv corresponda con las dependencias declaradas y bloqueadas.

Generar o actualizar el archivo de bloqueo

uv lock
ImportanteConservar uv.lock

En aplicaciones y proyectos colaborativos, uv.lock debe incluirse en Git. No debe agregarse a .gitignore.

El archivo .venv/, en cambio, no debe almacenarse en el repositorio.

Ejecutar comandos dentro del entorno

Ejecutar un script

uv run python main.py

También puede utilizar:

uv run main.py

Ejecutar un módulo

uv run python -m pytest

Ejecutar pruebas

uv run pytest

Ejecutar Ruff

uv run ruff check .

Para aplicar formato:

uv run ruff format .

Ejecutar una aplicación FastAPI

Primero agregue las dependencias:

uv add fastapi "uvicorn[standard]"

Ejecute el servidor:

uv run uvicorn main:app --reload

Activar manualmente el entorno virtual

Aunque uv run evita la activación manual, algunos IDE o flujos tradicionales pueden necesitarla.

Linux con Bash o Zsh

source .venv/bin/activate

Para salir:

deactivate

Windows con PowerShell

.\.venv\Scripts\Activate.ps1

Para salir:

deactivate

Windows con CMD

.venv\Scripts\activate.bat

Para salir:

deactivate

Activación bloqueada en PowerShell

Cuando PowerShell impida ejecutar Activate.ps1, puede habilitar temporalmente los scripts únicamente para la sesión actual:

Set-ExecutionPolicy `
    -Scope Process `
    -ExecutionPolicy Bypass

Después:

.\.venv\Scripts\Activate.ps1

La configuración desaparece al cerrar PowerShell.

Una opción más sencilla es no activar el entorno y utilizar directamente:

uv run python main.py

Crear solamente un entorno virtual

No todos los directorios necesitan convertirse inmediatamente en proyectos administrados mediante pyproject.toml.

Para crear únicamente un entorno virtual:

uv venv

Para seleccionar una versión:

uv venv --python 3.12

Para asignar otro nombre:

uv venv entorno-desarrollo --python 3.12

Activación en Linux

source .venv/bin/activate

Activación en Windows

.\.venv\Scripts\Activate.ps1

Trabajar con requirements.txt

uv ofrece dos enfoques diferentes.

Enfoque de compatibilidad con pip

Cree un entorno:

uv venv

Instale las dependencias:

uv pip install -r requirements.txt

Sincronice exactamente el archivo:

uv pip sync requirements.txt

Este enfoque es útil cuando se mantiene una estructura tradicional basada en requirements.txt.

Migrar a un proyecto uv

Inicialice el proyecto:

uv init

Importe las dependencias:

uv add -r requirements.txt

Después de verificar el resultado, las dependencias principales estarán declaradas en pyproject.toml y bloqueadas en uv.lock.

Configurar JupyterLab

Agregue JupyterLab y el kernel como dependencias de desarrollo:

uv add --dev jupyterlab ipykernel

Inicie JupyterLab:

uv run jupyter lab

Para registrar un kernel con nombre propio:

uv run python -m ipykernel install \
  --user \
  --name mi-proyecto \
  --display-name "Python - mi-proyecto"

En Windows PowerShell, el mismo comando puede escribirse así:

uv run python -m ipykernel install `
    --user `
    --name mi-proyecto `
    --display-name "Python - mi-proyecto"

Ejecutar herramientas temporales con uvx

uvx permite ejecutar herramientas Python sin instalarlas permanentemente en el proyecto.

Por ejemplo, para ejecutar Ruff:

uvx ruff check .

Para ejecutar una versión específica:

uvx ruff@0.12.0 check .

Para ejecutar Black:

uvx black .

Configurar un IDE

Visual Studio Code

Abra la carpeta del proyecto y seleccione el intérprete correspondiente.

Linux

mi-proyecto/.venv/bin/python

Windows

mi-proyecto\.venv\Scripts\python.exe

En Visual Studio Code:

  1. presione Ctrl + Shift + P;
  2. busque Python: Select Interpreter;
  3. seleccione el intérprete ubicado en .venv.

PyCharm

En PyCharm:

  1. abra Settings;
  2. seleccione Project: nombre-del-proyecto;
  3. abra Python Interpreter;
  4. seleccione Add Interpreter;
  5. elija Existing environment;
  6. seleccione el ejecutable de .venv.

No cree un segundo entorno desde PyCharm cuando uv ya haya generado .venv.

Configuración recomendada de Git

Un archivo .gitignore básico puede contener:

# Entorno virtual
.venv/

# Bytecode de Python
__pycache__/
*.py[cod]

# Pruebas
.pytest_cache/
.coverage
htmlcov/

# Herramientas
.ruff_cache/
.mypy_cache/

# Jupyter
.ipynb_checkpoints/

# Editores
.vscode/
.idea/

# Variables sensibles
.env
.env.*

Los siguientes archivos sí deben almacenarse en Git:

pyproject.toml
uv.lock
.python-version
README.md
Código fuente
Pruebas
Advertencia

Nunca almacene contraseñas, tokens, claves de API o archivos .env con información sensible en un repositorio.

Reproducir un proyecto existente

Cuando se clona un proyecto que ya contiene pyproject.toml y uv.lock, el proceso es:

git clone URL_DEL_REPOSITORIO
cd NOMBRE_DEL_PROYECTO
uv sync
uv run python main.py

No es necesario copiar la carpeta .venv de un computador a otro. Cada sistema debe reconstruirla mediante uv sync.

Solución de problemas

uv no se encuentra en Linux

Compruebe si existe el ejecutable:

ls -la "$HOME/.local/bin/uv"

Agregue el directorio al PATH:

export PATH="$HOME/.local/bin:$PATH"

Para hacerlo permanente en Bash:

echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc

uv no se encuentra en Windows

Compruebe el archivo:

Test-Path "$env:USERPROFILE\.local\bin\uv.exe"

Agregue temporalmente el directorio:

$env:Path += ";$env:USERPROFILE\.local\bin"

Pruebe:

uv --version

La versión de Python no está disponible

Instale explícitamente la versión:

uv python install 3.12

Después selecciónela:

uv python pin 3.12

Sincronice nuevamente:

uv sync

El entorno parece desactualizado

uv sync

Para forzar la reinstalación de los paquetes:

uv sync --reinstall

Limpiar la caché

Consulte el tamaño de la caché:

uv cache dir

Limpie los archivos no utilizados:

uv cache prune

Para eliminar completamente la caché:

uv cache clean
Advertencia

uv cache clean obliga a descargar nuevamente los paquetes cuando vuelvan a necesitarse.

Problemas con certificados corporativos

En algunas redes institucionales, el tráfico HTTPS pasa por certificados internos. Puede indicarse a uv que utilice el almacén de certificados del sistema.

Linux

export UV_SYSTEM_CERTS=true

Windows PowerShell

$env:UV_SYSTEM_CERTS = "true"

Después, repita el comando que estaba fallando.

No utilice opciones que desactiven la validación TLS salvo que comprenda sus implicaciones de seguridad y controle la red utilizada.

Consultar información detallada

Active la salida detallada:

uv --verbose sync

También puede consultar la ayuda de un comando:

uv help
uv help sync
uv help python
uv help add

Desinstalar uv

Linux

Primero puede limpiar los datos administrados:

uv cache clean
rm -rf "$(uv python dir)"
rm -rf "$(uv tool dir)"

Elimine los ejecutables:

rm -f "$HOME/.local/bin/uv"
rm -f "$HOME/.local/bin/uvx"

Finalmente, retire de .bashrc o .zshrc las líneas de configuración agregadas para uv.

Windows

Antes de eliminar el ejecutable, puede limpiar la caché:

uv cache clean

Elimine los ejecutables del usuario:

Remove-Item `
    "$env:USERPROFILE\.local\bin\uv.exe" `
    -ErrorAction SilentlyContinue

Remove-Item `
    "$env:USERPROFILE\.local\bin\uvx.exe" `
    -ErrorAction SilentlyContinue

Remove-Item `
    "$env:USERPROFILE\.local\bin\uvw.exe" `
    -ErrorAction SilentlyContinue

Después puede retirar el directorio .local\bin del PATH del usuario mediante la configuración de variables de entorno de Windows.

Flujo mínimo recomendado

Para comenzar un proyecto desde cero:

uv init --python 3.12 mi-proyecto
cd mi-proyecto

uv add numpy pandas
uv add --dev pytest ruff

uv run python main.py
uv run pytest
uv run ruff check .

Para abrir un proyecto existente:

git clone URL_DEL_REPOSITORIO
cd NOMBRE_DEL_PROYECTO

uv sync
uv run python main.py

Conclusiones

uv permite mantener separadas tres responsabilidades que con frecuencia se mezclan en una instalación tradicional de Python:

  • la instalación del intérprete;
  • la administración de dependencias;
  • la creación del entorno de ejecución.

En Linux, puede instalarse dentro del directorio del usuario mediante el script oficial. En Windows, el mismo procedimiento puede realizarse desde una sesión normal de PowerShell, sin modificar la configuración global del equipo y sin utilizar una cuenta de administrador.

Para proyectos nuevos, el flujo recomendado es utilizar uv init, declarar las dependencias mediante uv add, conservar uv.lock en Git y ejecutar el código con uv run. Este enfoque reduce la necesidad de activar manualmente los entornos y facilita la reproducción del proyecto en otros computadores.
